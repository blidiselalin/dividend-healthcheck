## 2. Information collected

DividendScope processes only data needed to authenticate users, operate invite-only portfolios, and provide educational analytics. Depending on how you use the hosted service, that may include:

| Category | Examples |
|---|---|
| Google account identity | Subject identifier provided by Google OAuth |
| Email address | Account email used for login and access control |
| Display name | Name provided by the identity provider, when available |
| Internal user identifier | Application user id used to scope database records |
| Portfolio holdings | Tickers, share quantities, cost basis |
| Purchase journal | Recorded buys/sells and related lot data |
| Deposits | Monthly deposit records used for portfolio tracking |
| Dividend transactions | Broker-reported or recorded dividend receipts and related tax fields when present |
| Portfolio preferences | In-app preferences that affect display or guidance |
| Imported broker-statement data | Parsed fields from authenticated broker-file imports |
| Access-request status | Requests and approvals for invite-only beta access |
| Application security and error logs | Diagnostic events needed to operate and secure the service |
| Infrastructure logs | IP and proxy logs that may be generated by the hosting provider |
| Support communications | Messages you send when requesting help or exercising data rights |

Exact fields depend on features you use. Portfolio values and holdings are stored as user-scoped records in PostgreSQL when you use an authenticated real portfolio.

## 3. Information not intentionally collected

The hosted beta is not designed to collect:

- Broker login credentials
- Broker trading passwords
- Payment-card details
- Government identification documents
- Bank-account credentials

DividendScope does not provide automatic IBKR account credential storage or live broker login synchronization in this beta. Authenticated users may upload supported broker statement files; those files are processed for import and are not a substitute for broker credentials.

## 4. Purposes

Personal data is processed to:

- Authenticate users (Google OAuth and related session controls)
- Provide portfolio calculations and educational analytics
- Process authenticated imports
- Display dividend analytics and research views
- Maintain security and prevent unauthorized access
- Diagnose application failures
- Respond to support and data-rights requests
- Operate the controlled invite-only beta

## 9. Security

Controls used for the hosted beta include, at a high level:

- HTTPS for the public application endpoint
- Google OAuth for sign-in
- User-scoped PostgreSQL records for portfolio data
- Restricted administrative access
- Secret storage outside source control
- Backups (process documented for operators)
- Dependency and code scanning as they are enabled for the repository

No online service can be guaranteed completely secure. Report suspected vulnerabilities privately using [SECURITY.md](SECURITY.md).
